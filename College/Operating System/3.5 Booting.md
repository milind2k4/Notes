# Booting

**Booting** (or "bootstrapping") is the process a computer performs to start itself from a powered-off state. It's a sequence of operations that finds, loads, and starts the **Operating System Kernel**.

The four main goals of the boot process are to:
1. Determine the configuration and health of the system's hardware.
2. Find and load the core OS programs (the kernel) from a storage device into RAM.
3. Initialize the OS data structures and hardware drivers.
4. Pass control to the OS, which then starts the user-space environment.

### The Boot Sequence

The process happens in a specific, chronological order:

#### 1. Power On & Firmware (BIOS/UEFI)

When you press the power button, the computer's power supply sends a "power good" signal to the motherboard. The CPU then begins executing code from a non-volatile (permanent) chip on the motherboard. This chip contains the **firmware**.

- **Firmware:** This is low-level software that controls the hardware.
    - **BIOS (Basic Input/Output System):** The legacy firmware. It's stored in a **ROM (Read-Only Memory)** chip.
    - **UEFI (Unified Extensible Firmware Interface):** The modern, more powerful replacement for BIOS.

#### 2. POST (Power-On Self Test)

The first action of the firmware (BIOS or UEFI) is to run **POST**. This is a health check for all the required hardware.

- It checks the CPU, RAM, storage devices (disks), and peripherals (keyboard, etc.).
- If POST fails (e.g., bad RAM), the computer will stop and report an error, often as a series of **beep codes** or an on-screen message.

#### 3. The Bootloader

Once POST is successful, the firmware's next job is to find and load the **Bootloader**. A bootloader is a small program whose only job is to load the main Operating System.

- **Legacy (BIOS-MBR) Method:**
    1. The BIOS checks the **boot order** (a setting you can change, e.g., "1st: USB, 2nd: Hard Drive").
    2. It looks at the first sector of the bootable device, called the **Master Boot Record (MBR)**.
    3. This MBR contains the _first-stage bootloader_.
    4. The BIOS loads this tiny program into RAM and passes control to it.

- **Modern (UEFI-GPT) Method:**
    1. The UEFI firmware looks for a special partition on the disk called the **EFI System Partition (ESP)**.
    2. This partition contains larger, more complex bootloader files (e.g., `bootx64.efi`).
    3. The UEFI firmware directly executes this file, which is the _first-stage bootloader_ (e.g., GRUB, Windows Boot Manager).

#### 4. Kernel Loading

The first-stage bootloader is often just smart enough to load a _second-stage bootloader_, which has more features.

1. The **second-stage bootloader** (like GRUB on Linux or Windows Boot Manager) is loaded. This program _can_ read file systems (like NTFS, ext4).
2. It reads its configuration file to know _what_ to load.
3. It finds the **Kernel** file on the disk (e.g., `vmlinuz` on Linux, `ntoskrnl.exe` on Windows) and an **initramfs** (a temporary file system with drivers).
4. It loads both the Kernel and the initramfs into RAM.

**(Note:** Older systems like MS-DOS used specific files like `IO.SYS` and `MSDOS.SYS`, which held the kernel, and `CONFIG.SYS` to load drivers. This is no longer how modern systems work.)

#### 5. Hand-off to the OS

1. The bootloader's job is done. It passes control to the kernel, which is now in RAM.
2. The kernel "wakes up" and runs.
3. It uses the drivers in the **initramfs** to initialize hardware (like disk controllers).
4. It mounts the real, permanent **root file system**.
5. It starts the **init process** (the first user-space process, with PID 1, such as `systemd` on Linux).
6. The `init` process then takes over and starts all the other system services (networking, login screen, GUI, etc.), completing the boot.
